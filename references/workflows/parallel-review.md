# Round 1 并行独立评审（子 agent 模式）

Step 4 的默认执行方式：每个专家由一个**独立子 agent** 生成评审意见，互相不可见，消除单上下文顺序生成的锚定效应（anchoring）。真实的独立性是 Step 5 分歧检测、Step 6 辩论和 Step 7 裁决信息量的前提。

## 何时启用

- 运行环境支持子 agent（如 Agent / Task 工具）→ **默认启用**
- 运行环境不支持子 agent → 回退到单上下文模式：主线程逐个专家生成，但必须在生成每个专家意见前显式忽略此前专家的倾向（回退时在出场卡末尾标注一行：`⚠ 本轮为单上下文模拟独立评审`）

## 子 agent 派发规则

对 Step 2 确定的每位专家（3 核心 + 1-2 情境），**并行**派发一个子 agent。

每个子 agent 的 prompt 必须包含且仅包含：

1. **任务说明**：你是产品评审团中的一位专家，独立评审一份 PRD。你看不到其他专家的意见，不要猜测他们。
2. **PRD 全文**（或可读取的文件路径）
3. **Step 1 intake 的问答记录与 skip log**（如有）
4. **该专家的人设定义**：从 `references/personas/experts-{cn|intl}.md` 中截取该专家完整章节（含身份、核心框架、表达 DNA、内在张力、典型问题、Round 1 输出模板、Round 1 通用约束）
5. **输出格式硬约束**（见下）

**隔离要求（硬约束）**：

- 禁止在 prompt 中携带其他专家的身份、倾向或观点
- 禁止携带主线程对 PRD 的任何预判或摘要倾向（只给事实性 intake 记录）
- 子 agent 只做研究和输出，不写文件、不改代码

## 子 agent 返回格式（硬约束）

每个子 agent 必须返回以下结构，主线程原样收录，不得润色改写倾向标签：

```
【专家名】
倾向标签: 倾向 GO | 倾向 NO-GO | 倾向 CONDITIONAL
致命缺陷: 无 | [Cagan 四风险之一]: [一句话描述]（仅当倾向 NO-GO 且认为不可恢复时填写）
理由: ≤ 80 词，用该专家的语气与框架
追问: 一个希望 PM 回答的问题
```

- **禁止数字评分**（与全局护栏一致）
- "致命缺陷"字段直接对接 `verdict-logic.md` 的 Step A 硬否决检查

## 主线程收录规则

1. 所有子 agent 返回后，按出场卡顺序拼装 Round 1 评审块，**逐字保留**倾向标签、致命缺陷和理由，仅可修正明显的格式问题
2. **格式归一化**：子 agent 常把人设模板里的装饰前缀一起抄进返回（如 `📍 追问：`、`理由：` 后多余空行、`【专家名】` 重复）。主线程在拼装时统一清洗为 Step 4 规定的四字段结构，去除 emoji 前缀和重复标签——但**不得改动倾向标签、致命缺陷判定和理由文字本身**。清洗只动格式，不动内容。
3. 若某个子 agent 失败或返回不符合格式：重试一次；仍失败则该专家降级为主线程单上下文生成，并在该专家意见末尾标注 `（本条为主线程代生成）`
4. Step 5 的分歧检测、Step 7 的票数统计，只依据子 agent 返回的倾向标签

## Step 6 辩论的衔接

辩论**仍在主线程进行**（不派发子 agent）。主线程基于两份独立的 Round 1 输出做对抗综合：

- 引用必须来自子 agent 的原文，不得虚构专家未说过的话
- 若辩论中需要"回应对方"，主线程以该专家的人设框架推演，但不得修改其 Round 1 的倾向标签
- 独立子 agent 意见与主线程共识冲突时，**以子 agent 意见为准**——共识不能覆盖独立评审
